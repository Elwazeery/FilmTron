# TRON — Optional On-Device Creative AI: Native Editor Integration
**Decision date:** 2026-10-21. **Status:** DESIGN ONLY; not yet implemented/tested; no model download or training.
**Shared authority:** [GemiMCP hybrid ADR](https://github.com/GemiTron88/GemiMCP/blob/main/docs/architecture/07-LOCAL-CREATIVE-AI-HYBRID-20261021.md), [delegation contract](https://github.com/GemiTron88/GemiMCP/blob/main/contracts/CREATIVE-AI-DELEGATION.v1.md), [creative knowledge/workflows](https://github.com/GemiTron88/GemiMCP/blob/main/docs/creative-ai/CREATIVE-KNOWLEDGE-AND-WORKFLOWS.v1.md), [TRON persona/training](https://github.com/GemiTron88/GemiMCP/blob/main/docs/creative-ai/TRON-PERSONA-AND-TRAINING-STRATEGY.v1.md).
**Architecture amendment:** earlier "no local model/no chatbot" contracts are amended by an **OPTIONAL** shared, opt-in on-device TRON agent. ChatGPT remains primary cloud creative director and its existing **direct native MCP tools stay functional WITHOUT TRON**. No duplicate public MCP, no bundled model download, no paid API and no mandatory AI to use the editor.

## 1. Product UI / lifecycle
- One optional **Creative AI / TRON tab** with selectable Manual, ChatGPT (cloud), TRON Local (offline) modes. When local inactive, zero model VRAM footprint; app start, ordinary editing, render and startup Desktop Agent must NEVER preload weights.
- Opening TRON tab may auto-load ONLY after an explicit saved user preference/consent; default is a visible **Start TRON** action. Local runtime serves all four apps using **one loaded model**, not four inference processes. Active tab obtains scoped lease keyed by app instance+project+user; tab close releases lease and app close releases all app leases.
- **Unload when final lease AND active approved job end**. Multiple simultaneously open editors share one model with separate project isolation. A ChatGPT request cannot silently auto-load a closed local model: request explicit locally approved headless job lease/consent or return CONSENT_REQUIRED/LOCAL_AI_NOT_ACTIVE.
- Cancel and unload at safe native transaction boundary; report partial edits, preserve readback/undo, reconcile idempotency after crash. Confirm actual unload using inference runtime loaded-model endpoint plus GPU observation. The Ollama service may remain idle but **no model weights in GPU**. File stays on disk.
- RTX 3050 6GiB VRAM, 64GiB RAM, dual Xeon Windows: candidate **pinned Qwen3.5 4B Q4** for initial inference ONLY, single concurrency, 4K context baseline, measure headroom WITH native GPU renderer. Do not claim usable performance until native test; fall back or stop when GPU pressure threatens preview/export.
- Display loading/ready/running/draining/unloaded/error state, GPU claim/limitations, Cancel, Stop/Unload, actual tool receipts. No hidden background watcher, GPU daemon, model updates or unapproved downloads.

## 2. Command and security invariant
- TRON uses the **same real typed native command bus** that UI/CLI/GemiMCP use; it must never implement fake actions, generic OS-shell or visual click replay as core execution.
- Shared GemiMCP: public/cloud MCP, direct product route and federation, delegated `creative_ai.*` tools, grants, approvals, durable jobs and outbound-only agent. Product repo: actual native engine, project, stable capability manifest, readback, undo, native safety and local TRON tab adapter.
- ChatGPT director can (A) execute directly via existing product MCP without TRON; (B) provide goal+bounded plan to GemiMCP delegation; TRON refines microsteps only inside immutable allowed capabilities, expected revision, resource/project/device ownership, budget and approvals; (C) local user controls TRON offline via native commands.
- No second on-disk login/licensing writer: retain Gemi Access / auth.gemitron.net for cloud, GemiGuard entitlement where required. Local offline owned-project editing works without online session. Untrusted input includes media metadata, imported captions, image layer names and assets; instructions embedded in that content are not trusted.
- Minimal project-only context; no secrets in model prompt; private assets remain on device unless explicitly approved and minimized; no auto media upload to VPS, no unauthorized render/download/network.
- Native expectedRevision + idempotencyKey + scoped object IDs. Do not overwrite manual concurrent changes; each potentially destructive write uses staged preview/diff and approval. Verified receipt = actual native mutation + readback/preview + reopen/export if requested, not an LLM assertion.
- TRON voice: natural Egyptian Arabic Gen Z, practical and artistically opinionated; distinguish chat voice from final deliverable locale. An Arabic Saudi/Kuwaiti brief must keep requested advertising dialect, fonts and protected brand copy.

## 3. Creative operating loop
INTAKE real brief and source rights -> DISCOVER currently implemented capabilities -> INSPECT actual native project and asset dimensions -> PLAN in small typed actions -> PREPARE diff/preview -> APPROVE risky writes -> APPLY bounded idempotent step -> READBACK true native revision -> REVIEW actual preview+quality rubric -> REFINE at most two automatic iterations -> DELIVER native editable artifact and real proof. Return UNSUPPORTED / GPU pressure / missing provider rather than invent advanced rendering or media generation.

## 4. Training and quality policy
No training/fine-tuning as Phase 1. Shared TRON compact persona and versioned creative KB plus product-specific overlays and real native tool schemas come first. Build rights-safe golden workflows and negative tests; fine-tune only if blind evaluation proves repeated issues in tool calling or persona consistency.
**Important:** Unsloth advises **against Qwen3.5 4-bit QLoRA** due to quantization differences; guide estimates ~10GiB for 4B bf16 LoRA, above local 6GiB VRAM. Treat full-capability QLoRA on reference Windows PC as NOT FEASIBLE UNTIL independently proven. Optional later LoRA using suitable GPU/approved environment, never silently train or download. Reference: https://unsloth.ai/docs/models/qwen3.5/fine-tune

## 5. Acceptance
No "TRON ready" without: a real owner-started model session and measured load/VRAM/unload, local offline scoped edit+undo+project reopen, truthful preview, malicious injected content rejection, parallel tab close and process crash cleanup, explicit consent for remote ChatGPT delegation, direct MCP path unchanged, and negative wrong device/project/revision tests.

## 6. FilmTron specialization — Story Editor / Colorist / Sound Finisher
**Reality:** repo reports 295 native command descriptors and 32 semantic film tools. This is a declared mapping, not proof of all live GemiMCP client paths. Native wgpu and media playback/render share GPU with on-demand TRON inference.
**TRON film overlay:**
- Convert brief into hook/value/CTA shot list, audience and aspect ratio, story pace, exact source clip IDs/rights, rational frames/timebase, track structure, title-safe areas, music beats and captions.
- Use actual `film.*` commands: inspect bin/source/timebase, create/trim/ripple/roll/transition/title with no float-time drift; preserve edits/relink/undo and native project. No hallucinated footage or sound.
- Color and sound: protect neutral monitor/scopes and source color space, skin tones, white balance and luminance; ensure voice intelligibility, lip/audio sync and render loudness. Avoid arbitrary LUTs/zoom transitions for spectacle.
- Preview at shot boundaries and target output; verify exact duration/frame count, decode exported MP4 and audio, reopening a real .fcproj, inspect affected revisions. Speech-to-text / generative voice requires a real installed provider, not assumed from local planning model.
**Golden journey:** 15-second two-footage/music promo, hook 0–3s/value 3–11s/CTA 11–15s adjusted to actual sources, timeline edits using integer/rational timebase, restrained transitions, captions and audio, inspect and revise, export decoded MP4 and native editable project, undo/reopen and media QC.
**Touchpoints before code:** `crates/automation/src/gemimcp.rs`, `crates/automation/src/security.rs`, native NLE timeline command specs, project exporter. Ensure the GPU has headroom; yield model generation during heavy playback/render.
**No training fork:** film-specific edit grammar and scene/beat retrieval is enough initially; fail safely on unsupported transcript or semantic video understanding.
